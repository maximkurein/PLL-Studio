# Штатный USB EVB без внешнего SPI-моста

Экспериментальный транспорт для схемы **8V97051 EVB Rev A от 14.05.2015**. Реализованы запись R7→R0 и чтение регистров через FT2232 и SC18IS602.

**Аппаратная проверка 08.11.2026 прошла после временного замыкания R2.** Стандартный путь `Engine::read_register` и `EvbBridge::transfer` прочитал R0–R7 с совпадением всех конфигурационных битов. Изменение INT=100→101→100 подтверждено обратным чтением во всех трёх состояниях. Получены DEV_ID=6, REV_ID=1, SPI_ERROR=0. Оба RF-выхода отключены и это подтверждено readback. Результаты не являются измерением частоты, мощности или фазового шума.

Штатная последовательность работает без дополнительной очистки INT SC18IS602 и без добавленных задержек. В расширенном аудите также проверены оба документированных варианта SCLKE (1 с mode 0; 0 с mode 1) на 58/115 кГц. Полный 200-байтовый буфер показал, что четыре байта SPI-ответа находятся на ожидаемых позициях 0–3. Исходный короткий MUX-тест без дополнительных задержек вернул FFFFFFFF при MUX_OUT=VDDD и 00000000 при MUX_OUT=GNDD. Ошибка программной последовательности не обнаружена; причина ранее полученных нулей однозначно не установлена.

R2 в линии MUX_OUT → MISO на PDF-странице 1 схемы помечен **NP**; пользователь подтвердил его отсутствие на своём экземпляре и временно замкнул площадки для проверки. При разомкнутом R2 чтение невозможно. Предыдущий тест R5 был подтверждён пользователем по трём миганиям LD. USB/MPSSE и запись/чтение GPIO SC18IS602 также проверены: шаблонам 0x0A/0x04/0x0E соответствуют 0x0B/0x05/0x0F (сравниваются GPIO1–GPIO3).

## Подключение

1. Подключите USB платы к компьютеру, где работает desktop-приложение или `pll-server`. В веб-режиме используется USB сервера, а не браузера.
2. Закройте Timing Commander и приложения, открывающие FTDI. Внешний SPI-мастер должен быть отключён. Проверьте JP3 и питание платы; JP1 (MUTE) и JP2 (CE) — по руководству EVB.
3. Откройте **«Подключение» → «Штатный USB платы EVB» → «Найти EVB»**.
4. Выберите именно свою плату. Поиск показывает FT2232 с VID:PID **0403:6010**, bcdDevice **0500/0700** (FT2232C/D или H); такой же USB ID бывает у программаторов и других плат. Список устройств не доказывает, что найден синтезатор. Если сомневаетесь, сравните список до и после подключения EVB.
5. Нажмите **«Подключить USB»**. Приложение занимает только интерфейс A (USB interface 0), синхронизирует MPSSE, проверяет ACK от SC18IS602 и настраивает SPI. Регистры синтезатора при этом **не записываются**, авто-запись выключается.
6. Проверьте настройки частоты и выходов, затем нажмите **«Записать»** в верхней панели. Эта операция может включить RF-выход согласно выбранной конфигурации. Начальный профиль приложения включает RF_OUTA.
7. На экране **«Регистры»** нажмите **«Прочитать все»** и проверьте совпадения. Для SPI mode 0 используйте SCLKE = 1. Чтение до первой успешной полной записи блокируется: без известного R2 нельзя безопасно переключить и восстановить MUX_OUT.
8. Захват проверьте по светодиоду LD на плате и измерительному прибору. Через штатный USB отдельный вывод LD не подключён — надпись **«LD неизвестен»** в приложении ожидаема.

**«Отключить USB»** возвращает симулятор и освобождает интерфейс. После ошибки передачи транспорт блокирует дальнейшие SPI-операции; отключитесь, проверьте питание/кабель и подключитесь заново. Регистры после ошибки считаются неизвестными. При необходимости снова выполните полную запись. Отключение связи не выключает уже работающий RF-выход.

## Драйверы операционной системы

Используется уже включённая в проект библиотека `nusb` 0.1, без DLL Timing Commander и без внешней библиотеки libusb. Требования следуют из [документации nusb 0.1.14](https://docs.rs/nusb/0.1.14/nusb/#platform-support).

- **Windows:** интерфейсу **A** выбранной EVB нужен драйвер **WinUSB**. Обычный FTDI VCP/D2XX-драйвер не предоставляет доступ через nusb. Установить WinUSB для конкретного интерфейса можно через [Zadig](https://zadig.akeo.ie/); проверьте VID:PID и Interface 0, не заменяйте драйвер USB-концентратора или канала B. PLL Studio не меняет драйверы автоматически. После замены Timing Commander может потерять доступ к этому каналу; для возврата восстановите официальный драйвер FTDI через диспетчер устройств.
- **macOS:** nusb использует IOKit. Если канал захвачен Apple/FTDI VCP-драйвером или другим приложением, подключение завершится ошибкой. Закройте использующие его программы; наличие `/dev/cu.usbserial…` само по себе не означает доступность MPSSE. Автоматическая выгрузка системных драйверов и D2XX-обход в этой реализации отсутствуют. Не отключайте SIP ради подключения.
- **Linux:** нужны права на USB-устройство и свободный интерфейс A. При привязке `ftdi_sio` администратор должен освободить конкретный интерфейс и настроить права; приложение не отвязывает драйверы автоматически и не требует запуска всего GUI от root.

Если получена ошибка **SCL удерживается в 0**, проверьте питание SPI-части и JP3. По схеме подтяжки SCL/SDA R40/R37 питаются от VDD_SPI через LDO U3; работающий USB FT2232 ещё не подтверждает питание этой шины. Сообщение содержит байт GPIO: 0xF8 означает низкие AD0/AD1/AD2. Эта диагностика не доказывает причину неисправности и не является измерением напряжения.

## Что доступно

Штатный путь по схеме, PDF-страница 2:

- U5 FT2232, канал A: AD0/TCK → SCL, соединённые AD1/TDI и AD2/TDO → SDA.
- U4 SC18IS602: A2=A1=A0=0, семибитный адрес **0x28** (байты на шине: 0x50 для записи, 0x51 для чтения).
- SS0 → CSB, MOSI → SDI, SPICLK → SCLK, MISO ← MUX_OUT синтезатора.
- JP2/CE, JP1/MUTE и LD не соединены с управляющими GPIO USB-моста. Соответствующие кнопки отключены; поля RF_OUTA_EN/RF_OUTB_EN доступны через SPI. Модель использует предположение CE=1/MUTE=1, а не измеренные уровни этих выводов.

Для штатного пути записи SPI не требуется перепайка. Для readback нужна проводимость через R2; на схеме этот компонент не установлен (NP). Проверять и дорабатывать плату следует при отключённом питании по её фактической ревизии; номинал перемычки не задан в схеме и должен быть проверен по требованиям сигнального тракта. Для схемы с изменённым монтажом или другой ревизии сначала сверьте соединения. Предупреждения о логике **3.3 В** и изоляции U4 относятся к подключению **внешнего** SPI-мастера и остаются действующими.

## Реализация и ограничения

`crates/pll-core/src/transport/evb.rs` реализует `Link`. RPC `list_evb_usb` возвращает только дескрипторы кандидатов; `connect` с `kind: "evb_usb"` и выбранным `device` открывает конкретное устройство по bus/address/serial. Нет автоматического подключения к первому FTDI или сканирования всех адресов I²C.

Инициализация SC18IS602: F0 02 — MSB first, mode 0, SPI около 115 кГц; F6 00 — SS0 остаётся выходом выбора ведомого. Один SPI-кадр задаётся I²C-сообщением `01 + четыре байта слова, старший первым`, затем STOP. SC18IS602 удерживает SS0 на все 32 такта. Результат читается отдельным I²C-чтением четырёх байтов без Function ID. ACK при чтении адреса используется как признак завершения; INT не подключён, F1 для его очистки не нужен.

SCL/SDA реализованы через GPIO-команды MPSSE 0x80/0x81/0x87. Для логической 1 линия переводится во вход, для 0 — в выход с нулевым значением. Так поддерживаются подтяжки Rev A и **clock stretching** SC18IS602 без активного драйвера высокого уровня и без команд, доступных только новым FTDI. Это медленнее аппаратного MPSSE clock engine: каждый бит требует USB-обмена. Частые свипы и массовый readback могут занимать секунды. Точная скорость на плате не измерена.

При обработке USB IN удаляются два статусных байта из каждого пакета FTDI. Есть ограничение времени USB, I²C и ожидания готовности. Повторяется только адресное чтение при NACK занятого SC18IS602; SPI-запись после ошибки автоматически не повторяется. EEPROM, VID/PID и прошивка FTDI не меняются. Программа не сбрасывает всё USB-устройство и не управляет аппаратным RESET SC18IS602.

Совпадение ACK подтверждает ответ устройства по адресу 0x28, а не модель синтезатора. Проверка реальной платы должна включать readback/DEV_ID, светодиод LD и измерение RF_OUTA. Отключение USB обнаруживается при следующем обмене; фонового чтения LD здесь нет.

## Источники и проверка

- [Локальный комплект производителя](VENDOR_SOURCES_ru.md): схема Rev A, PDF-страница 2. Бинарная personality `.tcp` не декодировалась, установщик Timing Commander не запускался.
- [NXP SC18IS602/602B/603 Rev.04](https://www.nxp.com/docs/en/data-sheet/SC18IS602_602B_603.pdf), §7.1.1–7.1.6 и §7.1.10: адрес, SPI-буфер, занятость, настройка интерфейса и SS/GPIO.
- [FTDI AN_108 v1.5](https://www.ftdichip.cn/Support/Documents/AppNotes/AN_108_Command_Processor_for_MPSSE_and_MCU_Host_Bus_Emulation_Modes.pdf), §3.1, §3.6, §3.7, §5.1: синхронизация, GPIO, loopback, Send Immediate; [FT_SetBitMode](https://ftdichip.com/Support/Knowledgebase/ft_setbitmode.htm) — режим и маска направления.
- [Linux ftdi_sio.h](https://github.com/torvalds/linux/blob/master/drivers/usb/serial/ftdi_sio.h): числовые USB vendor requests и индекс канала. Использованы определения протокола, код драйвера не копировался.

Тестовый I²C-ведомый декодирует фактические переходы GPIO и проверяет SPI-пакет, MSB-first, последний NACK, STOP, ожидание clock stretching, NACK без повторной записи и обработку обрыва. Отдельные тесты проверяют FTDI status bytes, таймаут, запрет неподдерживаемых GPIO, неизвестное состояние после неполной записи и readback после полной записи через виртуальный кристалл.

Пассивная диагностика из терминала (не занимает интерфейс и не посылает команды):

```bash
cargo run -p pll-core --example evb_usb_list
```

Для проверки регистров с двумя отключёнными RF-выходами доступен пример:

```bash
cargo run -p pll-core --example evb_usb_register_test -- --write-read
```

Он записывает известную конфигурацию, сверяет R0–R7, проверяет DEV_ID, затем при успешном readback проверяет INT=100→101→100. При несовпадении останавливается. Команды отключения RF не считаются физически подтверждёнными до достоверного readback. Диагностика `evb_usb_mux_test` дополнительно проверяет GPIO1–GPIO3 SC18IS602 и постоянные уровни MUX_OUT, возвращая режим SDO.

## Проверка записи по светодиоду LD

Если R2 не установлен и readback недоступен, запись R5 можно проверить визуально по LD1:

```bash
cargo run -p pll-core --example evb_usb_ld_test -- --blink
```

После паузы 5 с пример трижды задаёт LD_PIN_MODE=3 (High) на 2 с, затем LD_PIN_MODE=0 (Low) на 2 с. В конце задаётся LD_PIN_MODE=1 (Digital Lock Detect). Из регистров PLL меняется только R5; RF-настройки не записываются. Зарезервированные D20/D19 сохраняются равными 1 по даташиту, таблицы 10A/10B. Пример возвращает стандартный режим LD, а не неизвестное прежнее содержимое R5.

Наблюдаемые три мигания подтверждают доставку SPI-записи в R5 синтезатора. Успешная отправка команд без визуального наблюдения этого не доказывает. Такая проверка не подтверждает чтение регистров, захват частоты или весь набор настроек R0–R7.

## Расширенный аудит readback

```bash
cargo run -p pll-core --example evb_usb_read_audit
```

Пример выполняет запись конфигурации с отключёнными RF-выходами, проверяет постоянные уровни MUX_OUT, содержимое 200-байтового буфера SC18IS602 и чтение R7 при SCLKE=1/mode 0 и SCLKE=0/mode 1 на 58/115 кГц. Между запросом R7 и тактированием ответа допустимы I²C-команды настройки моста: они не генерируют дополнительных SPI-тактов. Пример завершает работу записью стандартного mode 0/115 кГц, SCLKE=1 и отключёнными RF-выходами. Дополнительные очистка INT и пауза 5 мс используются только для диагностики; обычный транспорт в них не нуждался в успешном аппаратном тесте.

Зарегистрированные слова стандартного теста INT=100: R0=00320000, R1=00008011, R2=1C004F42, R3=0080000B, R4=00832094, R5=00580005, R6=E0D42B06, R7=C2C00087. При INT=101 R0=00328000, R6=E0D42D06. Статусные и неописанные биты не участвуют в сравнении конфигурации; DEV_ID, REV_ID и SPI_ERROR проверяются отдельно.

## Проверка через интерфейс приложения

08.11.2026 полный путь проверен в веб-интерфейсе с реальной EVB: «Подключение» → «Найти EVB» → выбор Dual RS232 USB 0:1 → «Подключить USB». После подключения авто-запись выключена, CE/MUTE недоступны, LD отмечен как неизвестный. В «Архитектуре» отключён RF_OUTA, RF_OUTB уже выключен. Через «Регистры» → «Записать всё» → «Прочитать всё» получены восемь отметок readback ✓. R4=00832094 подтверждает RF_OUTA_EN=RF_OUTB_EN=0, R7=C2C00087 подтверждает DEV_ID=6, REV_ID=1, SPI_ERROR=0.

При проверке исправлено отображение RO/sticky: теперь карточки и соответствующие биты используют последнее валидное чтение регистра, декодированное ядром Rust. До первого чтения отображаются «—»/«?», а конфигурация для записи остаётся отдельной. В исправленной версии поля DEV_ID=6 и REV_ID=1 подтверждены непосредственно на экране после повторного аппаратного чтения.

В тот же день проверена нативная оболочка Tauri на macOS: собран и запущен debug-пакет `target/debug/bundle/macos/PLL Studio.app` со встроенным фронтендом (`tauri://localhost`). Через desktop-интерфейс найдена Dual RS232 USB 0:1, выполнены подключение, «Записать всё» и «Прочитать всё». Все R0–R7 получили отметку readback ✓; сохранённая конфигурация пользователя использована с обоими отключёнными RF-выходами. Считаны R0=00188018, R1=00008029, R2=1E004E42, R3=0080000B, R4=00864094, R5=00580005, R6=E0D42906, R7=C2C00087. Поля R7 на экране показали DEV_ID=6, REV_ID=1 и SPI_ERROR=0. R4 подтвердил RF_OUTA_EN=RF_OUTB_EN=0. Отметки совпадения сравнивают только определённые записываемые поля; статусные и неописанные биты могут отличаться от слова для записи. Авто-запись осталась выключенной, CE/MUTE недоступны, «LD неизвестен» ожидаем. Чтение выполнено с временно замкнутым R2.

Через «Планировщик» → «+шаг» проверена перестройка 2480→2490→2500 МГц при fPFD=50 МГц. После каждого перехода через desktop-кнопку «Прочитать всё» прочитаны новые делители: на 2490 МГц R0=00188020 (INT=49, FRAC/MOD=4/5), R6=E0D42A06; на 2500 МГц R0=00190000 (INT=50, FRAC=0), R1=00008011, R6=E0D42B06. В обоих случаях DIG_LOCK=1 и BAND_SEL_DONE=1, SPI_ERROR=0. Карточки R6 показали «Захват» и «Завершён». Состояние подтверждено регистрами; частота на RF-разъёме прибором не измерялась, оба выхода оставались отключены.

При выключенном ограничении «Шаг сетки» кнопки ± используют текущий шаг сетки синтезатора: на 2500 МГц он стал 25 МГц, поэтому первый шаг назад дал 2475 МГц. Для возврата использован явный шаг 5 МГц, затем исходные R0=00188018 и R1=00008029 восстановлены через редактор и записаны. Итоговое чтение всех регистров подтвердило исходную конфигурацию 2480 МГц, R6=E0D42906 (DIG_LOCK=1, BAND_SEL_DONE=1), R7=C2C00087 (SPI_ERROR=0). Настройки ограничения шага возвращены к исходным. «LD неизвестен» в верхней панели относится к недоступному отдельному выводу, а статус цифрового захвата читается из R6. Readback хранит последнее чтение: после перестройки для актуального статуса требуется новое чтение.
